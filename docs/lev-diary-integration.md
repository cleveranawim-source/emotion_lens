# 마음 렌즈 ↔ Lev Diary 연동 설계

> 목적: **마음 렌즈(emotion_lens)** 를 감정 캡처 프런트엔드로 삼아, 학생이 확인한 감정을
> **Lev Diary(감정일기 앱)** 의 일기 흐름으로 넘기는 방법을 정리한다.
> 두 앱은 스택이 다르므로(아래) "느슨한 연결 → 점진적 통합" 순서를 권장한다.

## 1. 현재 상태 (as-is)

| | 마음 렌즈 | Lev Diary |
|---|---|---|
| 스택 | React + Vite | 단일 HTML |
| 저장 | 브라우저 `localStorage` (서버 없음) | Firebase (Auth + Firestore) |
| 규모 | 개인/기기 단위 | 3학년 × 10반, 약 800명 |
| 데이터 성격 | 표정 단서 → 감정 후보 → **학생이 확인** | 감정 + 상황 서술, 교사 소통 |

핵심: 마음 렌즈는 **"자기 인식(표정을 힌트로 내 감정을 스스로 고르기)"**, Lev Diary는
**"기록·소통(감정일기 + 교사 피드백)"**. 연결하면 *캡처 → 성찰 → 기록·소통*의 흐름이 완성된다.

## 2. 데이터 계약 (JSON 스키마 `emotion-checkin/v1`)

마음 렌즈의 **JSON 내보내기**가 만드는 이식용 포맷. 이것이 두 앱 사이의 계약이다.

```jsonc
{
  "app": "emotion-lens",
  "schema": "emotion-checkin/v1",
  "exportedAt": "2026-07-05T00:00:00.000Z",
  "count": 3,
  "records": [
    {
      "id": "uuid",
      "createdAt": "2026-07-05T00:00:00.000Z",
      "selectedEmotionId": "sadness",   // 학생이 최종 확인한 감정 (권위 있는 값)
      "selectedEmotion": "슬픔",
      "predictedEmotion": "낮은 에너지: 슬픔",  // 앱 추정 (참고용)
      "confidence": 42,                  // 표정 단서 강도 (참고용, 정답 아님)
      "note": "시험 때문에 마음이 무거웠다",
      "analysis": { /* 그룹·후보·막대 세부 (선택) */ },
      "includesFaceCapture": false
    }
  ]
}
```

> **얼굴 이미지(`capturedImage`)는 내보내기에서 의도적으로 제외**한다. 미성년자 얼굴 데이터를
> 기기 밖으로 옮기지 않는다(용량·개인정보). 이미지가 필요하면 개별 카드 다운로드를 쓴다.

**권위 규칙**: `selectedEmotionId`(학생이 고른 값)가 항상 우선한다. `predictedEmotion`·`confidence`는
보조 메타데이터일 뿐 일기 본문의 감정으로 승격하지 않는다.

## 3. 연동 옵션 (세 단계, 결합도 순)

### 옵션 A — 수동 JSON 브리지 ✅ *지금 구현됨*
- 마음 렌즈에서 `JSON` 내보내기 → Lev Diary에 "가져오기" 창구를 만들어 붙여넣기/업로드.
- **장점**: 두 앱을 전혀 건드리지 않고 오늘 바로 됨. 결합도 0.
- **단점**: 사람이 파일을 옮겨야 함. 실시간 아님.
- **적용처**: 교사가 활동 후 한 번에 반 데이터를 이관, 개인 백업/기기 이전.

### 옵션 B — 핸드오프(딥링크 / postMessage) *다음 단계 권장*
- 기록 저장 시 마음 렌즈가 **한 건**을 Lev Diary로 넘겨 일기 작성 화면을 미리 채움.
- 구현: (1) 같은 기기 새 탭이면 URL 파라미터
  `levdiary.example/new?src=emotion-lens&emotion=sadness&note=...&at=ISO`,
  (2) iframe 임베드면 `window.postMessage`로 `emotion-checkin/v1` 단건 전달.
- **장점**: "캡처 → 바로 일기 쓰기" UX. 여전히 느슨한 결합.
- **단점**: Lev Diary에 수신 라우트/핸들러 1개 추가 필요. URL 길이(note) 주의.
- **주의**: 얼굴 이미지·민감 정보는 URL로 넘기지 않는다.

### 옵션 C — 공유 Firestore *완전 통합, 신중히*
- 마음 렌즈가 Lev Diary와 **동일 Firebase 프로젝트/Auth**로 로그인해 같은 컬렉션에 직접 기록.
- **장점**: 실시간·단일 데이터·교사 대시보드에서 즉시 반영.
- **단점**: 마음 렌즈에 Auth 도입, Firestore 보안 규칙, 설정 공유 필요. 결합도 최고.
  익명/공용 키오스크 사용과 **로그인 기반 개인 데이터**가 충돌 → 계정 모델부터 정해야 함.
- **적용처**: 마음 렌즈를 Lev Diary의 정식 입력 모듈로 승격할 때.

## 4. 필드 매핑 (마음 렌즈 → Lev Diary 일기)

> Lev Diary의 실제 Firestore 필드명은 **연동 전 확인 필요**. 아래는 의미 기준 매핑.

| 마음 렌즈 | → | Lev Diary 일기(예상) |
|---|---|---|
| `selectedEmotion` / `selectedEmotionId` | → | 감정 태그(주 감정) |
| `note` | → | 일기 본문(초안) |
| `createdAt` | → | 작성 시각 |
| `predictedEmotion` + `confidence` | → | (선택) "앱이 본 표정 힌트" 메모 — 참고용 각주 |
| `includesFaceCapture` | → | 저장 안 함(연동에서는 항상 이미지 제외) |

## 5. 개인정보 원칙 (미성년자 · 카메라)

1. 얼굴 이미지는 기기 밖으로 내보내지 않는다(JSON·URL·Firestore 모두 제외).
2. 넘기는 것은 **학생이 스스로 확정한 감정 + 서술**뿐. 앱 추정은 참고용 각주로만.
3. 반 단위 시각화가 필요하면 개인 식별 없이 **익명 집계**(예: "오늘 우리 반 무드 분포")로.
4. 공용 기기에서는 사용 후 `다음 사람`/`전체 지우기`로 정리(앱에 구현됨).

## 6. 권장 로드맵

1. **A(완료)**: JSON 내보내기로 데이터 이식·백업 확보.
2. **B**: Lev Diary에 `emotion-checkin/v1` 단건 수신(딥링크 or postMessage) 추가 → "캡처 후 일기 쓰기".
3. **집계**: 교사 발표용 익명 반 무드 보드(옵션, 개인정보 안전).
4. **C**: 계정 모델이 정해지면 공유 Firestore로 정식 통합.

2절 계약과 4절 매핑을 그에 맞춰 갱신할 것._
